# 拔掉 ST-Link 后试车与事后读数

2026-10-04 17:12:58 记录版已编译，尚未烧录。本轮增加 RAM 记录功能，前馈角度、触发条件和原有保护参数保持当前值。上一轮用户试车仍有明显位移；同一上电周期读取到新增启动项累计触发数为 0，需要运行时间线定位原因。

## 用户操作

1. 在 C 板工程目录执行原烧录命令：`powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Tools\Flash-CBoard.ps1`。
2. 拔掉 ST-Link，重新选中 Pi 任务4，回中后短按 START，再按小车模式3 TIME 的发车键。尽量在选任务后的 10 秒内发车，并录像。
3. 试车结束后保持 C 板供电，不复位、不开始新的任务4/5/6。选任务满 40 秒后记录会自动冻结；接回 ST-Link 告诉助手已接好，由助手读取、导出。用户只需提供视频，不必自己运行读取脚本。

记录位于 RAM；断电、复位或重新烧录会丢失。选中另一轮任务4/5/6会覆盖上一轮；切到其他任务会冻结并保留上一轮。

## 记录内容与范围

- 自动记录任务4/5/6，从收到原始 `CONTROL_ENABLED` 开始，包含 READY 阶段；记录不依赖前馈已成功启用，因此能捕获门控拒绝。
- 25 Hz、1000条，最多约40秒；任务终态或转入其他任务也会冻结。
- 保存球位置/速度、视觉/IMU年龄、过滤及原始加速度、任务标志、球控/前馈/启动状态、启动触发数、PD和各前馈、期望角/最终角命令请求/电机反馈角。
- 最终角命令字段表示经过原保护后的请求，不证明 CAN 已成功入队；真实响应要结合电机反馈角和故障字段判断。
- 加速度控制值来自同一 IMU 快照；原始加速度只作诊断，可能来自相邻 IMU 输出。40 ms 之间的短暂状态可能漏采，但冻结时保留最终累计触发数。
- 占用64,080字节静态RAM，没有Flash写入、动态分配或串口发送；记录调用在原CAN动作之后。

## 助手读取

使用与试车固件对应的 ELF：

```powershell
.\Tools\Read-LaunchTrace.ps1 -FirmwarePath .\Firmware\H_BallBalance_CBoard_LaunchTrace_20261004.elf
```

脚本从 ELF 查找缓存地址，读取前后两份头部和记录，并在电脑上比较全部Flash字节。初始化前关闭目标配置的默认 `examine-end` 写入；显式目标命令只有读取，没有 halt/reset/program。生成 `build/launch-traces/<时间>/trace.csv`、`summary.json` 和同名 ZIP。中文 ELF 路径通过复制到 ASCII 相对路径处理，校验、解码均使用同一快照。

`-PrepareOnly` 只准备读数计划，不启动 OpenOCD。未冻结、头部变化、格式不符或固件不一致时拒绝解码，不把这些情况当成有效试车数据。
