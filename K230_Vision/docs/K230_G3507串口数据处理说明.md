# K230 与 G3507 串口处理说明

## 1. 串口设置

```text
波特率：115200
数据位：8
校验位：无
停止位：1
帧格式：$名称,参数...#
```

接线：

```text
K230 TX → G3507 RX
K230 RX ← G3507 TX
两块板必须共地
```

## 2. K230 发送内容

| 数据帧 | 含义 | 3507处理方式 |
|---|---|---|
| `$LINE,error,angle,confidence#` | 巡线误差、线路角度、可信度 | 用于控制转向，约每40 ms更新 |
| `$LOST#` | 红线丢失 | 停车或进入找线保护 |
| `$CROSS,1#` | 十字路口 | 产生一次十字路口事件 |
| `$TJUNC,-1#` | 左侧有支路 | 根据路线决定左转或直行 |
| `$TJUNC,0#` | 正面T字，前方截止 | 根据路线选择左转或右转 |
| `$TJUNC,1#` | 右侧有支路 | 根据路线决定右转或直行 |
| `$NUM,n,confidence#` | 单个目标数字 | 在等待目标状态保存数字 |
| `$ROOM,n,confidence,direction#` | 多数字中目标数字的方向 | `-1`为左，`1`为右 |

`LINE`字段说明：

```text
error < 0：红线偏左
error > 0：红线偏右
angle：用于提前判断弯道方向
confidence：巡线可信度，范围0～100
```

3507转向可以先使用：

```c
turn = K_ERROR * error - K_ANGLE * angle;
```

建议先把 `K_ANGLE` 设为0，只调直线巡线；直线稳定后再逐渐增加角度补偿。

## 3. 3507 发送内容

3507读取到起点目标数字后，需要发给K230：

```text
$SET_TARGET,n#
```

例如目标为4号病房：

```text
$SET_TARGET,4#
```

这样K230在路口识别到多个数字时，只会发送数字4对应的 `ROOM`。

## 4. 3507处理原则

### 巡线

收到 `LINE` 后更新巡线误差和角度。超过约300 ms没有收到新 `LINE`，应停车保护。

收到 `LOST` 后立即停止正常巡线，不能继续使用旧的误差值。

### 路口

K230在路口存在期间约每200 ms重复发送 `CROSS` 或 `TJUNC`。

3507不能每收到一次就重复计数或重复转向，应采用锁存：

```text
第一次收到路口帧 → 执行一次路口处理
后续重复帧       → 忽略，只表示车辆仍在该路口
超过500 ms没有路口帧且车辆已驶离 → 允许识别下一个路口
```

### 数字

```text
画面中只有1个数字   → K230发送NUM
画面中有多个数字    → K230不发NUM，只发送目标ROOM
```

3507建议：

- 只在等待目标状态处理 `NUM`；
- 收到 `NUM` 后保存目标，并发送 `SET_TARGET`；
- 只在路口状态处理 `ROOM`；
- 使用 `ROOM` 前检查其中的数字与当前目标一致。

## 5. 3507需要增加的协议

当前3507解析器如果还没有 `TJUNC`，需要增加：

```c
VISION_EVENT_TJUNC
```

解析规则：

```text
$TJUNC,-1#  左侧支路
$TJUNC,0#   正面T字
$TJUNC,1#   右侧支路
```

方向只允许 `-1、0、1`，其他值直接丢弃。

## 6. 简单处理流程

```c
switch (event.type) {
case VISION_EVENT_LINE:
    line_error = event.value1;
    line_angle = event.value2;
    line_confidence = event.value3;
    break;

case VISION_EVENT_LOST:
    Car_Stop();
    break;

case VISION_EVENT_NUM:
    target_digit = event.digit;
    Send_SetTarget(target_digit);
    break;

case VISION_EVENT_ROOM:
    if (event.digit == target_digit) {
        target_direction = event.direction;
    }
    break;

case VISION_EVENT_CROSS:
case VISION_EVENT_TJUNC:
    if (!junction_locked) {
        junction_locked = true;
        Handle_Junction(event);
    }
    break;
}
```

关键点：

1. UART中断只接收字节，不要直接控制电机。
2. 主循环解析 `$...#` 完整帧。
3. `LINE`用于连续控制。
4. `LOST`用于安全停车。
5. `CROSS/TJUNC`必须去重。
6. `NUM`确定目标，`ROOM`确定目标在路口的左右方向。

## 7. 基础任务 1/2/3 当前扩展协议

基础任务代码使用以下路口帧，旧版不带纵坐标的
`$CROSS,1#` 和 `$TJUNC,type#` 不再作为任务输入：

```text
$CROSS,1,junction_y#
$TJUNC,type,junction_y#
```

- `junction_y`：路口横向红线中心在 K230 的纵坐标，范围 `0~479`；
  数值越大表示路口越靠近车体。
- `type=-1`：左侧 T 支路。
- `type=0`：正面 T 口。
- `type=1`：右侧 T 支路。
- K230 连续 3 帧确认后，在路口仍可见期间约每 200 ms 重复发送。
- G3507 只有在 `junction_y` 达到触发阈值后才进入编码器接近阶段。

起点目标握手：

```text
K230  -> G3507: $NUM,n,confidence#       （约每100 ms重复）
G3507 -> K230:  $SET_TARGET,n#           （未确认时周期重发）
K230  -> G3507: $TARGET,n,0#             （目标锁定确认）
```

病房数字匹配：

```text
K230 -> G3507: $ROOM,n,confidence,zone#   （约每100 ms重复）
```

去程使用 `ROOM` 决定方向；返程忽略全部 `NUM` 和 `ROOM`，只按
G3507 保存的路径栈执行逆动作。
