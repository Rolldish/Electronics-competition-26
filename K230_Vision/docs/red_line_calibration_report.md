# 红线 LAB 阈值真机调参报告

日期：2026-07-22

## 1. 调参流程

### 1.1 初次标定（calibrate_red.py）

在正常光照下运行 `calibrate_red.py`，得到初步建议值：

```
(29, 74, -3, 55, -7, 39)
```

该值已写入 `drug_car/config.py`、`main.py` 和
`tools/red_line_debug.py`。

### 1.2 发现误框问题

运行 `red_line_debug.py` 验证时，画面中几乎所有物体都被红色框包围，只有全黑画面时才显示 `LINE LOST`。

**原因分析**：`A_MIN=-3` 太松，LAB 色彩空间中 A 通道负值代表绿色方向，-3 意味着微微偏绿也进入阈值范围。

### 1.3 第一次收紧（正常光验证通过）

手动将 `A_MIN` 从 -3 提升到 15，只匹配真正偏红的像素：

```
(29, 74, 15, 55, -7, 39)  →  red_line_debug.py 验证通过
```

正常光照下，红色框准确包围红线，无明显噪点。同步到 `config.py`。

### 1.4 发现阴影遮挡问题

在有阴影遮挡红线的场景下，红线无法被检测到。

**原因分析**：阴影下红色像素亮度下降，`L_MIN=29` 太紧，暗部红色被排除。

在阴影场景下重新运行 `calibrate_red.py`，得到阴影建议值：

```
(11, 51, -3, 44, -7, 31)
```

### 1.5 全量合并失败

按取最宽范围合并两组阈值：

```
(11, 74, -3, 55, -7, 39)
```

再次出现严重误框。`A_MIN=-3` 再次成为问题，且阴影下 A_MIN 变负可能是因为 ROI 内混入了地面背景而非红线本身颜色变化。

### 1.6 最终折中方案（验证通过）

**策略**：只放宽 L 通道兼容阴影亮度变化，A/B 通道保持正常光的紧约束。

```
(11, 74, 15, 55, -7, 39)
```

| 场景 | 效果 |
|------|------|
| 正常光照 | 红色框准确包围红线，无误框 |
| 阴影遮挡 | 红线仍可被检测到 |

## 2. 最终参数

```python
RED_LAB_THRESHOLD = (11, 74, 15, 55, -7, 39)
```

| 通道 | 最小值 | 最大值 | 说明 |
|------|--------|--------|------|
| L（亮度）| 11 | 74 | 放宽 L_MIN 以兼容阴影暗部 |
| A（红-绿）| 15 | 55 | 收紧 A_MIN 排除绿色干扰 |
| B（黄-蓝）| -7 | 39 | 保持标定数据范围 |

## 5. 经验教训

1. **calibrate_red.py 容易统计到背景**：首次标定时 ROI 内混入非红线区域，导致建议值范围过大（尤其 A_MIN）。建议标定时确保 ROI 内红线占绝大多数。
2. **A_MIN 是关键的防误检参数**：LAB 中 A 通道接近 0 或为负时，许多常见物体都会被误匹配。正常红色物体的 A 值通常 ≥ 15。
3. **阴影问题优先调 L 通道**：阴影主要影响亮度，A/B 色度通道在阴影下通常不会剧烈变化。应先尝试只放宽 L，再考虑动 A/B。
4. **调试脚本的阈值独立于生产配置**：`red_line_debug.py` 不 import `config.py`，修改 `config.py` 后必须手动同步。
